# MiTV3 v10：可回退的归藏内存优化

## 范围与安全边界

- 基于 v9，兼容版升级为 versionCode 10 / `0.4.0-dev-mitv3.4`；普通版版本号不变。
- 目标实机为 MiTV3 / inception / Android 5.1.1（API 22）/ 固件 7.6.9.1426。
- 优先保证电视能正常启动、Home 返回、HDMI 和原生系统调节。仅优化归藏自身，不做整机“精简包”。
- 不停用、卸载、强停或降级小米桌面，不清理应用数据，不修改低内存阈值、后台进程数、CEC、开机信号源、更新组件或系统启动链。
- 用户的外观、字体、首页入口与顺序、轮播方式、天气城市、Home 和开机开关不迁移、不重置。

## 为什么保留原桌面

实机小米桌面当前为 3.50.1621。它是系统 Home 进程，使用系统共享 UID，且有小爱等服务绑定；不能视为普通、独立、随时可杀掉的第三方桌面。停止它的潜在影响不只是一张首页。

因此保持其原生职责，保留归藏中的“小米原桌面”“电视系统设置”和信号源入口；让系统自行管理其缓存进程。归藏现有 Home 前台服务和启动桥也保持不变，不为降低 PSS 而杀死承载 Home 返回的进程。

## 实现

1. **关闭设置即释放引用**：取消过期图片/毛玻璃回调，销毁预览 Surface，清空选项和页面容器引用。设置总览不再创建不可见的首页预览。关闭与重开使用独立的 dismiss 生命周期，避免旧对话框回调清理新页面。
2. **可取消图片任务**：`ImageRequest` 同时取消尚未执行的 Future 与主线程回调；已经开始的解码不强行中断。迟到结果不再回填已关闭界面，不回收可能被其他视图使用的 Bitmap。
3. **按显示用途解码**：读取图片尺寸后，按 `CENTER_CROP` 可见区域区域解码、采样并限制输出大小。实机主壁纸为 1920×1080，预览最多 960×540，缩略图最多 320×180。主壁纸保持实际渲染像素，不通过降低主画面清晰度省内存。项目自定义壁纸准备脚本仍统一输出 JPEG。
4. **按字节限制毛玻璃缓存**：从 12 张图片改为 2 MiB LRU；当前 384×216 ARGB 图片最多容纳 6 张（1,990,656 字节）。清除缓存不会 recycle 仍可能显示的图片。缓存上限不是整个应用内存上限，也不包含视图正在引用的图片。
5. **后台压力处理**：只有 Activity 不可见且收到 RUNNING_LOW / RUNNING_CRITICAL / BACKGROUND 或更强压力时，释放可重建材质和缓存。普通离开首页、UI_HIDDEN 和仍可见时不主动清除。保留主壁纸和 Home 服务，恢复时按需重建材质，不调用 `System.gc()`。
6. **诊断**：Activity dump 增加设置页残留标志、图片尺寸与分配字节数、待处理图片任务、LRU 大小和后台裁剪次数。不输出私有启动标记或天气坐标。

- 安装前拉取电视实际运行的 v9 APK，并将六份归藏私有偏好备份至仓库外。v10 与 v9 签名一致，使用覆盖安装；未卸载、未清数据，启动桥未更新。
- 已在实机安装 versionCode 10。主壁纸诊断为 1920×1080 / 8,294,400 字节。壁纸预览已截图检查，五张内置图片能正常浏览。
- 连续 10 轮打开设置/壁纸、快速上下浏览、按 Home 关闭：每轮均回到归藏主界面，`retainedPage=false`、`choices=0`、预览/选择任务不再 pending、材质回调 pending=0；测试前后的壁纸偏好完全一致。
- 从归藏实际 HDMI 1、HDMI 2 入口分别进入原生播放器并按 Home 返回，各 5 轮通过。这验证的是软件入口与返回路径，不代表 Zidoo / Switch 实际输出画面、声音、CEC 或游戏延迟已经验收。
- 从归藏打开小米原生系统设置，进入“图像”“声音”页面并按 Home 返回通过；未修改任何调节值。从归藏打开小米原桌面并按 Home 返回也通过。
- `home-appearance`、`home-items`、`frame-home` 与备份一致；Home/开机开关、轮播开关/间隔、天气显示/自动模式/手动城市与坐标逐项一致。壁纸选择随原有轮播自然变化，天气缓存正常更新，不将这些视为用户设置被重置。
- Home 服务仍处于前台运行，原生启动目标仍为归藏启动桥，`boot_auto_play=0`；原有六个禁用包列表不变，未增加系统精简操作。
- 本轮未看到归藏崩溃或图片解码失败。日志中出现的小米电视管家错误发生在安装前，不计作 v10 回归，也未借机改动管家组件。

## 内存观察

安装前 v9 在首页、5 分钟轮播状态下完成 10 分钟采样（每 2 分钟一次，共 6 次），PSS 为 40,203 / 51,151 / 40,327 / 51,175 / 40,243 / 40,143 KiB，即约 39.2–50.0 MiB。

v10 十轮设置测试每次回到首页后的 PSS 为约 39.6–43.7 MiB。之后在首页、同样 5 分钟轮播状态下，再完成 10 分钟、6 次采样：28,318 / 26,825 / 35,273 / 26,526 / 26,486 / 34,852 KiB，即约 25.9–34.4 MiB。整个观察期间主界面保持在前台，设置引用已释放、图片任务与材质回调均已结束；轮播正常，最后缓存为 1,990,656 字节。

这两轮首页观察中 v10 的占用较低，引用清理和缓存字节上限也由诊断验证。但它不是随机对照性能实验：数值受此前操作、GC、壁纸轮播、系统共享页和测量时机影响，不计算永久“节省百分比”，也不保证所有场景维持在这一范围。

## 未覆盖与回退

- 旧系统 `am help` 不提供可用的 `send-trim-memory` 命令，因此未强制制造低内存；策略通过单元测试，真实内存压力下的恢复仍需长期观察。不为测试而填满内存或杀系统进程。
- 本轮没有重启、断电或待机测试。v9 的历史启动验证不能当作 v10 新测试结果；下一次须与用户约定时间，再验证完整开机与待机/CEC。
- 回退时使用备份的同签名 v9：`adb -s TV_IP:PORT install -r -d guizang-tv-mitv3-v9-rollback.apk`，然后打开归藏一次。此为 debug 包的降级覆盖；若系统拒绝降级，应停止并分析错误，不用卸载或清数据来绕过。回退命令本轮未执行。
- 本次没有改变偏好结构，通常无需恢复 XML；不要覆盖用户安装后新增的设置。没有必要回退启动桥或修改小米系统配置。
- APK、私有偏好、截图、原始日志与测试脚本保留在仓库外，不纳入源码提交。
